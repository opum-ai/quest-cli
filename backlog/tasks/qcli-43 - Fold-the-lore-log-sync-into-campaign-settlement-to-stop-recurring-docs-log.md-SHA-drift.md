## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
docs/log.md drifts from dev after every backlog-handover campaign, and the drift is generated by the campaign machinery itself: PRs are squash-merged, which rewrites every branch SHA, so the SHAs lore recorded at branch time are not ancestors of dev afterwards. This has been fixed one-shot three times and re-opened each time -- QCLI-35 closed it for campaign doc-7, QCLI-39 closed it for doc-8, and as of doc-9 it is open again with 30+ unrecorded commits and recorded SHAs (e.g. 2e57876 for QCLI-32 / PR #48) that do not exist on dev.

The owner chose to fix the cause rather than keep filing per-campaign sync tasks: the log sync should run as part of campaign settlement, so the drift closes in the same session that opens it.

Scope note for whoever picks this up: this changes the settlement contract in .claude/skills/backlog-handover (SKILL.md stage R4i / reference/wave-loop.md section i), which is a documented fork of the opum-doc skill. The change is a deliberate behavioral divergence from upstream, so the skill Provenance section must record it -- this repo does not silently promote either side of a doc/cli disagreement.

Decide during planning where in the settlement order the sync belongs relative to the per-task Backlog writes and the single campaign-doc write, and whether it runs once per wave or once per campaign. Both are defensible; the task is to pick one, document the reasoning, and make it the contract.
